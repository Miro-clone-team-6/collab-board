# Продукт

CollabBoard — интерактивная доска для совместной работы: схемы, стикеры и
обсуждение идей. Несколько участников редактируют одну доску и видят изменения
друг друга. Результат проекта — открытый репозиторий и развёрнутое приложение.

Основной сценарий:

```text
создать доску → добавить элементы → пригласить участника → вместе изменить → сохранить
```

## Роли и доступ

Роль задаётся в рабочем пространстве — группе досок и участников.
Владелец управляет пространством и правами, редактор меняет содержимое,
наблюдатель просматривает. Доступ к доске выдаётся также по отзываемой ссылке
на просмотр или редактирование. Проверка прав требуется для каждого способа
доступа к данным.

## Требования к продукту

Перечисленные возможности пока не реализованы. Это объём продукта, не отчёт о готовности.

### Аккаунт и пространства

- Регистрация, вход, авторизация
- Личный кабинет и настройки
- Рабочие пространства: создание, приглашение участников
- Роли: владелец, редактор, наблюдатель
- Лендинг

### Доски

- Создание, переименование, копирование, удаление
- Поиск и фильтры
- Корзина с восстановлением
- Доступ по ссылке (просмотр / редактирование), отзыв доступа

### Холст

- Бесконечный холст: перемещение и масштабирование
- Элементы: текст, стикеры, фигуры, изображения
- Линии и стрелки между элементами, двигаются вместе с ними
- Размер, цвет, положение; базовое форматирование текста
- Множественное выделение: перемещение, копирование, удаление
- Группировка элементов
- Undo / redo **своих** действий (не отменяет чужие)
- Экспорт в изображение: вся доска или выбранная область

### Совместная работа

- Realtime-редактирование без перезагрузки
- Курсоры участников и список тех, кто сейчас на доске
- Восстановление после потери соединения
- Комментарии к элементу или точке, ответы, «решено»
- История версий: просмотр и восстановление
- Уведомления в Telegram: приглашение, упоминание, ответ

### ИИ

- Генерация содержимого: черновик архитектуры по описанию, идеи-стикеры по теме
- Работа с выделенной областью: сгруппировать, резюмировать, дополнить
- Результат сначала показывается как предпросмотр — применить или отказаться

ИИ работает с содержимым доски, а не как чат сбоку.

## Требования к надёжности

- Повторная доставка изменения не создаёт дублей.
- После обрыва соединения участник получает актуальное состояние доски.
- Одновременные изменения и удаление редактируемого элемента обрабатываются согласованно.
- Undo отменяет свои действия; восстановление версии относится ко всей доске.
- Пользователи на разных экземплярах API видят общие изменения.

## Требования к поставке и эксплуатации

- Тесты основного поведения и CI для lint, typecheck, test и build на каждый PR.
- Контейнерный деплой и выпуск релиза через GitHub.
- Централизованные логи, метрики и отслеживание ошибок.
- Ограничения на размер файлов, число элементов и запросы к ИИ.
- Длительные задачи генерации и обработки файлов выполняются в фоне.
- Секреты хранятся вне Git: локально в `.env`, в CI — в хранилище секретов.

Эти требования не означают наличие соответствующей инфраструктуры в репозитории.

## Глоссарий

| Термин | Значение |
|---|---|
| Пространство (workspace) | Группа досок и участников с ролями |
| Доска (board) | Бесконечный холст с элементами |
| Элемент (element) | Объект на холсте: текст, стикер, фигура, изображение, соединитель |
| Соединитель (connector) | Линия или стрелка, привязанная к элементам |
| Версия (version) | Снимок доски в истории, к которому можно откатиться |
| Присутствие (presence) | Кто сейчас на доске и где его курсор |
