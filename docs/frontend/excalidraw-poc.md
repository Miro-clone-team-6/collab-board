# Исследовательский PoC Excalidraw

> Черновик: постоянное хранение, полноценный offline и Undo своих действий при конфликте не реализованы.

Изолированный редактор для сравнения с PoC из ветки `research/tldraw-poc`.
Ветка `research/excalidraw-sync-v2` обновляет протокол совместной работы. Предыдущие
результаты описаны в [исследовании синхронизации всей сцены](excalidraw-sync-research.md).

## Устройство

`apps/web/app/research/excalidraw/page.tsx` реэкспортирует страницу из `apps/web/src/_pages/research-excalidraw/`.
Страница задаёт высоту `100dvh`; редактор получает остаток под заголовком и панелью через flex и `min-h-0`.

Клиентский `ExcalidrawLoader` использует `next/dynamic` с `ssr: false` из-за браузерных API.
CSS подключён в `ExcalidrawEditor.tsx`, тема — через `next-themes`. Основные страницы не изменены.

Frontend использует `@excalidraw/excalidraw`, backend — `@nestjs/websockets` и `@nestjs/platform-ws`.
Пакет поддерживает React 19, но транзитивный `@radix-ui/react-tabs` и часть его зависимостей
объявляют только React 16–18. Есть peer-предупреждения; подавления и overrides не добавлялись.

## Запустить и проверить

1. Использовать Node.js 26 и pnpm из `packageManager`. Из корня запустить:

   ```bash
   pnpm install
   pnpm --filter api dev:excalidraw
   ```

2. В другом терминале выполнить `pnpm dev:web`. Открыть две вкладки
   `http://localhost:3000/research/excalidraw`, дождаться статуса подключения WebSocket.
   Команда API собирает и запускает Nest только с Gateway, без Prisma и PostgreSQL, на порту 3001.
   Одновременно обычный API на этом порту запускать не нужно.
3. Нажать «Добавить стикер»: появится жёлтый прямоугольник с привязанным текстом.
   Перетащить его, двойным кликом изменить текст, затем удалить. Проверить вторую вкладку
   после каждого действия и перезагрузки. Любые фигуры используют тот же канал синхронизации.
4. Для локального снимка использовать кнопки сохранения/восстановления, для PNG/SVG — меню экспорта.

Инструменты доступны в штатном UI. Проверялась небольшая сцена в Chromium.

| Возможность | Поведение установленного релиза |
| --- | --- |
| Бесконечный холст, zoom и pan | Камера, кнопки масштаба, инструмент «Рука», Space + drag |
| Фигуры | Прямоугольник, эллипс, стрелка и линия на панели |
| Текст | Отдельный текст и привязанный текст внутри фигуры |
| Аналог стикера | Кнопка создаёт прямоугольник с заливкой и привязанным текстом через `convertToExcalidrawElements` |
| Редактирование | Перемещение, ручки изменения размера, цвет контура и заливки |
| Группы и копирование | Множественное выделение, Ctrl+G, Ctrl+C/Ctrl+V, дублирование Ctrl+D |
| Undo/Redo | Стандартная история локального редактора |
| Изображения | Вставка файла, изображение хранится отдельно от элемента сцены |

но отсутствует в типах релиза. Экспорт использует прежние функции, а не unreleased `exportScene`.

## Сохранение сцены

`ExcalidrawEditor.tsx` получает API через `excalidrawAPI`. Сохранение вызывает `getSceneElements`,
`getAppState`, `getFiles`, затем `serializeAsJSON(elements, appState, files, "local")`.
JSON с изображениями попадает в localStorage под ключом `collab-board:research:excalidraw:scene:v1`.

Восстановление разбирает JSON через `loadFromBlob`, помечает отсутствующие в сохранении
элементы как удалённые, вызывает `addFiles` и `updateScene` с `CaptureUpdateAction.NEVER`,
очищает историю. Вместо localStorage можно
подключить HTTP-хранилище. См. [imperative API](https://plus.excalidraw.com/docs/sdk/excalidraw/api/props/excalidraw-api)
и [сериализацию](https://plus.excalidraw.com/docs/sdk/excalidraw/api/utils).
Сигнатуры сверены с `.d.ts` пакета: документация местами отстаёт.

Undo/Redo, выделение и камера в локальном снимке не сохраняются. Автосохранения в localStorage нет.
После перезагрузки приходит сцена сервера; локальный снимок восстанавливается только кнопкой
и при подключённом WebSocket заменяет общую сцену. Ключ общий для профиля и origin.
Квота localStorage ограничена, особенно с base64-изображениями. Ошибки доступа, квоты и чтения
показываются в панели; остаётся штатный экспорт в файл. Постоянного хранения на сервере нет.

## Realtime для collab-board

`apps/api/src/modules/research-excalidraw/excalidraw.gateway.ts` хранит одну фиксированную комнату
в памяти. Только `src/research-excalidraw.ts` регистрирует Gateway и `WsAdapter` в отдельном
исследовательском Nest-модуле без БД. Он запускается командой `pnpm --filter api dev:excalidraw`.
Обычные `dev`, `start` и запуск `dist/main.js` используют `AppModule` без исследовательского Gateway
и без настройки `WsAdapter`.
Это исследовательское исключение из обычного HTTP-прокси приложения: браузер подключается
напрямую к `/research/excalidraw` API через native WebSocket. Адрес берётся из `NEXT_PUBLIC_API_URL`
(по умолчанию `http://localhost:3001`), протокол преобразуется в `ws`/`wss`.

При подключении сервер отправляет `snapshot` с элементами, их ревизиями и файлами. Затем
клиент отправляет `patch` только с изменёнными элементами и их `baseRevision`. Создание
использует `null`, удаление сохраняет запись с `isDeleted: true`. Файлы передаются по ID
при первом использовании. Камера, выделение и инструменты остаются локальными.

Gateway принимает весь пакет, если актуальны все его базовые ревизии. Клиент отправляет
изменения разных стикеров отдельными пакетами. При перемещении или удалении стикера
прямоугольник и связанный текст отправляются вместе. Принятый пакет
получают все участники, включая автора. Устаревший пакет отклоняется, отправитель получает
актуальные записи и видит статус конфликта. Чистое удаление можно повторить один раз
с актуальными ревизиями. Если пользователь уже нажал Undo, клиент пропускает повтор
отклонённого удаления. Undo принятого удаления отправляется как новая правка.
Устаревшее редактирование tombstone отклоняется.

`excalidraw-room.ts` собирает сцену из подтверждённых элементов, одного ожидающего ответа
пакета и новых локальных правок. Входящие изменения применяются с `CaptureUpdateAction.NEVER`.
Сравнение ID, версии, nonce и признака удаления исключает эхо, а промежуточные правки
собираются коротким таймером. После обрыва или пяти секунд без ответа на правку клиент
показывает восстановление соединения и загружает новый снимок. Неподтверждённые пакеты
сброшенного соединения не отправляются повторно. Offline-правки и локальная история
при этом сбрасываются.

Ограничения одноразового демо:

- Первая принятая правка побеждает при конфликте одного ID. Текст и перемещение стикера
  пересекаются на элементе подписи. Отказ одного элемента отклоняет пакет этого стикера.
- Перезапуск сервера очищает комнату.
- Undo/Redo работает как обычное локальное редактирование. Ревизии защищают от устаревшей
  записи, но Undo может заменить чужое значение той же координаты после получения его ревизии.
- Нет курсоров, авторизации, ролей, масштабирования и постоянного хранения. Все посетители
  URL разделяют комнату. Кнопка восстановления localStorage тоже изменяет её для остальных.

Для онлайн-MVP с видимыми конфликтами сложность средняя. Нужны постоянное хранение,
подтверждение повторных запросов и обработка разрывов. Совместный Undo с учётом авторства,
слияние полей связанных элементов и полноценный offline остаются задачами высокой сложности.

## Проверки Sync v2

23 ноября 2026 временный Playwright-скрипт проверил две вкладки Chromium и реальный NestJS
Gateway. Для гонок скрипт удерживал исходящие пакеты до появления локальных изменений
с обеих сторон и выпускал их в обоих порядках. Состояние сервера читалось отдельным
подключением. Проверялись отправленные ID и базовые ревизии, координаты, подпись и tombstones.
24 ноября 2026 базовые сценарии повторены и дополнены регрессиями из ревью.

| Сценарий | Результат |
| --- | --- |
| A двигает X, B двигает Y | **PASS**. Оба перемещения сохранились в обоих порядках доставки |
| A и B двигают X | **PASS**. Первое перемещение принято, устаревшее отклонено, обе вкладки показывают позицию победителя |
| A удаляет X, B редактирует подпись X | **PASS**. В обоих порядках удалены прямоугольник и подпись. При доставке текста первым потребовалась одна повторная отправка удаления |
| A отменяет ещё не подтверждённое удаление X, затем получает правку B и отказ сервера | **PASS**. Повтора удаления нет, стикер сохранился с текстом B |
| A отменяет принятое сервером удаление X | **PASS**. Прямоугольник и подпись восстановились одним новым пакетом с ревизиями удаления. Это также сработало, когда Undo нажат до получения ACK, а сервер принял исходное удаление |
| A перемещает X и Y, пока ждёт ACK, B конкурирует только за X | **PASS**. Пакеты X и Y разделены, перемещение Y сохранилось в обоих порядках доставки |
| ACK удержан при открытом WebSocket | **PASS**. Клиент показал ожидание, затем восстановление, загрузил снимок и продолжил обмен без повтора старого пакета |
| A меняет текст X, B двигает X | **PASS** по сходимости, **FAIL** по сохранению обеих правок. Побеждает первый пакет, поскольку движение меняет и геометрию подписи |
| Новая вкладка, обновление страницы, обрыв WebSocket | **PASS**. Снимок восстановил состояние сервера, включая удаления. При автоматическом переподключении правка, сделанная без сети, сброшена |
| Эхо подтверждений | **PASS**. После завершения гонок вкладки не отправляли новые пакеты в течение контрольной паузы |
| Создание, восстановление локального снимка | **PASS**. Параллельное создание сохранило оба стикера. Восстановление снимка передало tombstones для элементов, которых в снимке не было |
| Undo/Redo локального действия, в том числе удаления | **PASS**. Обе команды синхронизируются. Изменение B на другом стикере сохранилось |
| A и B последовательно меняют одну координату X, затем A нажимает Undo | **FAIL** по авторству. Координата вернулась с 470 на 320, затерев правку B. Redo вернул 470 |

После переподключения стек Undo очищен. В проверенной версии Excalidraw кнопка могла
оставаться активной до первого нажатия. Нажатие не меняло сцену и не отправляло пакет.
Изоляция исследовательского Gateway проверена отдельно на обычном `AppModule` в режимах
`development` и `production` с заглушкой Prisma.

## Сравнение с tldraw

Сравнение опирается на код и отчёт в `research/tldraw-poc`; в текущую ветку они не переносились.
Демо tldraw использует внешнюю комнату `useSyncDemo`, Excalidraw — собственный минимальный Nest Gateway.

| Критерий | Excalidraw | tldraw |
| --- | --- | --- |
| Основной сценарий | Эскизы и диаграммы, характерный рисованный стиль | Расширяемая интерактивная доска |
| Заметки | Фигура с привязанным текстом | Отдельная note-фигура |
| Базовый редактор | Готовые фигуры, текст, история и экспорт | Готовые фигуры, текст, история и экспорт |
| Realtime SDK | Нужен собственный слой; есть низкоуровневые API | `@tldraw/sync`, серверный `TLSocketRoom` |
| Хранение в PoC | Память Nest-сервера + локальный JSON по кнопке | Внешняя временная демо-комната |
| Изображения в PoC | Файлы хранятся в памяти комнаты и включаются в снимок при подключении | Демо-загрузки отключены; нужно своё хранилище |
| Расширение модели | Набор типов элементов задан библиотекой; `customData` для метаданных | API custom shapes и tools удобнее для своих карточек |
| Production-лицензия SDK | MIT | Собственная лицензия, действующий ключ |

По [руководству tldraw sync](https://tldraw.dev/docs/sync), self-hosted sync требует своего
сервера, хранения и прав. Он сокращает работу над протоколом, но не заменяет backend продукта.

## Ограничения и пригодность

Плюсы: MIT, готовый UI, простой embed, открытый JSON и экспорт, привязанный текст и изображения.

Минусы: собственный realtime, менее удобные custom shapes, отсутствие note-инструмента,
большой граф зависимостей и peer-предупреждения Radix. Шрифты загружаются с CDN;
для автономности нужны локальные assets и `window.EXCALIDRAW_ASSET_PATH`, см.
[release notes](https://github.com/excalidraw/excalidraw/releases/tag/v0.18.0).

Большие сцены, нагрузка, мобильные устройства, Safari/Firefox и доступность не исследованы.
Excalidraw снижает лицензионные ограничения, tldraw сокращает работу над sync и своими объектами.
Минимальный realtime получился небольшим, но проверка конкурентных правок и reconnect остаётся
существенно большим объёмом работы, чем подключение готового sync SDK.

## Проверки первого PoC

`pnpm typecheck`, `pnpm lint` и `pnpm build` прошли под Node.js 26. Маршрут статически генерируется.
Есть прежнее предупреждение Steiger о `toggle-theme`; peer-предупреждения Radix описаны выше.
В песочнице lint Markdown падал из-за владельца Git-каталога; вне песочницы прошёл.

Playwright с имеющимся Chromium проверил все операции из таблицы, включая clipboard, drag-and-drop
изображения и скачивание PNG/SVG. После перезагрузки восстановлены ID элементов и файлы.
Повреждённый JSON не заменил сцену; превышение квоты показало ошибку. Необработанных JS-ошибок не было.
При SVG-экспорте в dev Turbopack worker подмножества шрифтов недоступен по `file://`;
Excalidraw предупреждает и выполняет работу в основном потоке. Экспорт при этом завершился.
На viewport 1440×1000 и 390×844 холст дошёл до нижнего края без прокрутки страницы.
Маршруты `/` и `/boards` вернули HTTP 200 без редактора; health-запрос главной не прошёл без API.
Инструменты проверки не добавлены в проект; браузерный smoke выполнен в dev, production проверен сборкой.

Дополнительный smoke в двух вкладках Chromium проверил кнопку стикера, начальную загрузку комнаты,
перемещение, изменение текста, удаление и получение актуальной сцены после перезагрузки.
Проверено восстановление как непустой сцены, так и удаления; в покое WebSocket не пересылает эхо.
