# PoC: Real-time Collaborative Whiteboard (Yjs + Konva + Socket.IO)

**Статус:** Базовая real-time синхронизация, разрешение конкурентных правок (CRDT) и оптимизация рендеринга реализованы и стабильны. Персистентное хранение состояния доски в PostgreSQL (через Prisma) находится в очереди на реализацию.  
**Дата актуализации:** Ноябрь 2026  

Данная реализация использует собственный слой синхронизации на базе Yjs и Socket.IO, обеспечивая бесконфликтное совместное редактирование без зависимости от платных или source-available SDK (в отличие от tldraw).

---

## 🏗 Архитектура и структура (Feature-Sliced Design)

Проект следует методологии FSD в рамках pnpm-монорепозитория.

### Frontend (`apps/web/src/features/board/`)
- **`model/`**: Бизнес-логика. Zustand store, хук синхронизации `useYjsSync.ts`, провайдер `yjsProvider.ts` и типы данных.
- **`ui/`**: Компоненты рендеринга на базе `react-konva` (`Whiteboard.tsx`, `ShapeRenderer.tsx`, `CursorsLayer.tsx`).
- **`realtime/`**: Инициализация Yjs Doc, настройка Socket.IO клиента и обработка бинарных данных.

### Backend (`apps/api/src/modules/whiteboard/`)
- **`whiteboard.gateway.ts`**: NestJS WebSocket Gateway. Хранит экземпляры `Y.Doc` в оперативной памяти (ключ: `boardId`). Обрабатывает входящие бинарные апдейты и рассылает их клиентам.

## ⚙️ Принцип работы синхронизации (Yjs CRDT)

В отличие от классического подхода "отправить весь JSON при изменении", здесь используется CRDT (Conflict-free Replicated Data Type), что гарантирует детерминированное разрешение конфликтов.

1. **Структура данных**: Состояние доски представлено одним `Y.Doc`. Внутри него:
   - `Y.Map` с именем `shapes`: ключ — `id` фигуры, значение — вложенный `Y.Map` со свойствами (`x`, `y`, `type`, `width` и т.д.).
   - `Y.Array` с именем `connections`: список связей между фигурами.
   - `Awareness`: отдельный механизм Yjs для ephemeral-данных (курсоры, которые не нужно сохранять в историю).
2. **Локальное действие (Zustand → Yjs)**: Когда пользователь перемещает фигуру, мы перехватываем действие `updateShape` в Zustand. Оно обновляет локальный стейт для мгновенного UI-отклика, а затем через `provider.doc.transact()` вносит точечное изменение в соответствующий `Y.Map` с меткой `origin: "local"`.
3. **Сетевая передача**: Yjs вычисляет минимальную бинарную дельту (binary update) и автоматически отправляет её через Socket.IO на сервер.
4. **Серверная обработка**: NestJS Gateway применяет дельту к своему `Y.Doc` через `Y.applyUpdate` и рассылает эту же дельту всем остальным клиентам в комнате (`boardId`).
5. **Удаленное обновление (Yjs → Zustand)**: На других клиентах срабатывает `observeDeep` на `provider.shapes`. Он определяет, какая именно фигура и какое поле изменились (через `event.path`), и точечно вызывает `updateShape` в локальном Zustand, заставляя React/Konva перерисовать только нужный элемент.

## 🚀 Ключевые оптимизации и решенные проблемы

В процессе разработки были выявлены и устранены критические проблемы производительности и совместимости:

| Проблема | Решение |
| :--- | :--- |
| **Проблемы бинарных данных в сборщике Next.js** | Сборщик (Turbopack/Webpack) мог некорректно обрабатывать бинарные данные `lib0`. *Решение*: Изоляция компонента доски через `next/dynamic` с `ssr: false`, что гарантирует стабильную работу в текущей конфигурации Turbopack/Turbo. |
| **Дрожание (jitter) чужих курсоров** | Yjs Awareness рассылает heartbeat-сообщения каждые ~500 мс, вызывая лишние ререндеры. *Решение*: Debounce (150 мс) на `awarenessObserver`, округление координат (`Math.round`) и глубокое сравнение стейта через `Map` перед вызовом `setState`. |
| **Спам сети при движении мыши** | *Решение*: Троттлинг обновлений курсора до 20 FPS (50 мс) и "мертвая зона" (deadzone) в 1 пиксель. Если координаты не изменились, обновление в Yjs не отправляется. |
| **Потеря свойств при перемещении** | При использовании обычного `observe` Yjs не триггерил изменения вложенных полей, а частичный апдейт затирал остальные данные. *Решение*: Переход на `observeDeep` с анализом `event.path` и использование предыдущего состояния фигуры как fallback для неизмененных полей. |
| **Производительность Konva** | Предупреждение о превышении лимита слоев (макс. 3-5). *Решение*: Объединение статичных элементов (фон, связи) и активных элементов (фигуры + Transformer) в 4 оптимизированных слоя `<Layer>`. |
| **"Висящие" курсоры при перезагрузке** | *Решение*: Явный вызов `provider.awareness.setLocalState(null)` в cleanup-функции `useEffect`, что заставляет курсор исчезнуть мгновенно при закрытии вкладки. |

## ✅ Текущие возможности

- **Холст**: Бесконечный холст с поддержкой Zoom (колесо мыши) и Pan (средняя кнопка мыши).
- **Фигуры**: Прямоугольник, круг, текст, стикер, изображение, группа.
- **Взаимодействие**: Drag-and-drop, изменение размеров (через Konva Transformer), выделение рамкой (LMB + Drag).
- **Real-time курсоры**: Отображение позиций и имен других пользователей с цветовой индикацией.
- **Разрешение конфликтов**: Полностью автоматическое (CRDT). Одновременное перемещение одной фигуры разными пользователями разрешается детерминировано на основе `clientID`.

## ⚠️ Ограничения и план развития (Roadmap)

1. **Хранение на сервере**: Состояние `Y.Doc` хранится **только в оперативной памяти** NestJS. При перезапуске сервера данные теряются. *План*: Интеграция с Prisma/PostgreSQL для персистентности (сохранение `Y.encodeStateAsUpdate` при отключении последнего клиента или по таймеру).
2. **Совместная история (Undo/Redo)**: Локальный Undo работает, но синхронизированный `Y.UndoManager` для всей комнаты еще не реализован.
3. **Удаленное выделение**: Отображение рамок выделения (selection bounds) для фигур, которые в данный момент редактируют другие пользователи, пока не реализовано.
4. **Масштабируемость**: При очень больших досках (>1000 фигур) текущая реализация `observeDeep` может требовать дополнительной оптимизации (виртуализация или разбиение на чанки).

## 📦 Зависимости

### Frontend (`apps/web`)
```json
{
  "dependencies": {
    "yjs": "^13.6.15",
    "y-protocols": "^1.0.6",
    "socket.io-client": "^4.8.1",
    "react-konva": "^18.2.10",
    "konva": "^9.3.14",
    "zustand": "^4.5.0"
  }
}

**Назначение:**
- **`yjs`** — CRDT-библиотека для бесконфликтной синхронизации данных в реальном времени.
- **`y-protocols`** — Протоколы для Yjs, включая `awareness` для ephemeral-данных (курсоры).
- **`socket.io-client`** — Клиентская часть Socket.IO для WebSocket-соединения с сервером.
- **`react-konva`** — React-обертка для Konva, позволяющая рендерить canvas-элементы как React-компоненты.
- **`konva`** — Библиотека для работы с HTML5 Canvas (отрисовка фигур, трансформации, события).
- **`zustand`** — Легковесный state manager для хранения состояния доски (фигуры, курсоры, соединения).

### Backend (`apps/api`)
```json
{
  "dependencies": {
    "@nestjs/websockets": "^10.3.0",
    "@nestjs/platform-socket.io": "^10.3.0",
    "yjs": "^13.6.15"
  }
}
**Назначение:**
@nestjs/websockets — Модуль NestJS для создания WebSocket Gateway.
@nestjs/platform-socket.io — Адаптер Socket.IO для NestJS WebSocket.
yjs — Серверная часть Yjs для хранения и синхронизации Y.Doc в памяти.

**Назначение:**
yjs и lib0: Использованы версии 13.6.15 и 0.2.88 соответственно для избежания багов с бинарными данными в Webpack. В корневом package.json добавлены pnpm.overrides для жесткой фиксации этих версий.

### 🛠 Как запустить и проверить


1. Убедитесь, что запущен Docker (для PostgreSQL, если требуется бэкенду) или что проверка БД временно отключена для тестов WebSockets.
   ```bash
    pnpm run infra:up
2. Из корня монорепозитория запустите API и Web:
   ```bash
   pnpm run dev:api
   # В другом терминале:
   pnpm run dev:web

3. Откройте две вкладки браузера по адресу: http://localhost:3000/whiteboard .
Сценарий проверки:
В первой вкладке создайте фигуру (например, стикер). Она должна мгновенно появиться во второй.
Перетащите фигуру в первой вкладке. Во второй вкладке она должна переместиться плавно, без рывков и потери свойств (размера, цвета).
⚖️ Сравнение с альтернативами (Excalidraw / tldraw)
