# Исследовательский PoC tldraw

> Черновик: архитектура self-hosted sync — гипотеза, её реализация и интеграция с NestJS не проверены.

Изолированный эксперимент для оценки готового редактора и совместной работы в collab-board.
Результаты получены в локальном dev-режиме в Chromium; нагрузка и мобильные устройства не проверялись.

## Устройство

Маршрут `apps/web/app/research/tldraw/page.tsx` реэкспортирует страницу из
`apps/web/src/_pages/research-tldraw/`. Серверная страница содержит предупреждение о тестовых
данных, клиентский `TldrawLoader` загружает редактор через `next/dynamic` с `ssr: false`.
CSS редактора импортируется в `TldrawEditor.tsx`; общие стили и существующие страницы не меняются.

`useSyncDemo` передаёт готовый store в `Tldraw`. Состояние редактора не проходит через
TanStack Query и не связано с API приложения. Зависимости эксперимента закреплены в
`apps/web/package.json`; версии существующих пакетов в lockfile сохранены.

Комната эксперимента:
`collab-board-research-tldraw-8c307fed-7c7b-476b-96ac-1560d2ac30b5`.
Она общая для всех посетителей этой страницы. UUID предотвращает случайное совпадение имён,
но не ограничивает доступ.

## Запустить и проверить

1. Из корня репозитория запустить frontend:

   ```bash
   volta run --node 26.13.1 pnpm dev:web
   ```

2. Открыть `http://localhost:3000/research/tldraw` в двух вкладках. Создать фигуру в одной,
   переместить её в другой и проверить передачу изменений в обе стороны.
3. Для проверки разных участников открыть тот же URL в другом профиле браузера или режиме
   инкогнито и подвигать курсор над холстом. По умолчанию tldraw хранит идентичность пользователя
   в localStorage, поэтому обычные вкладки одного профиля используют одного пользователя.
4. Проверить инструменты по таблице ниже. Использовать только вымышленные тестовые данные.

## Результаты проверки

| Возможность | Результат | Как проверено |
| --- | --- | --- |
| Бесконечный холст, zoom/pan | Работает из коробки | Масштабирование колесом с Ctrl и перемещение инструментом «Рука» меняют камеру |
| Фигуры | Работает из коробки | Созданы два прямоугольника, один перемещён мышью |
| Текст и стикеры | Работает из коробки | Созданы текст и заметка с текстовым содержимым |
| Стрелки | Работает из коробки | Стрелка соединяет две фигуры, обе привязки присутствуют в store |
| Выделение и группировка | Работает из коробки | Две фигуры выделены через Shift, Ctrl+G создаёт группу |
| Undo/Redo | Работает из коробки | Кнопки отменяют группировку и восстанавливают её |
| Совместное редактирование | Работает через `useSyncDemo` | Фигуры появились во второй вкладке, изменение из неё вернулось в первую |
| Курсоры участников | Работает через `useSyncDemo` | Курсор участника из отдельного контекста браузера отображается в первой вкладке |

Все восемь сценариев проверены в headless Chromium через Playwright. Временные инструменты
проверки не добавлены в зависимости проекта. На странице редактора не зарегистрировано ошибок
JavaScript. Маршруты `/` и `/boards` вернули HTTP 200 и отобразили прежние заголовки без редактора.
Существующий health-запрос главной страницы не прошёл, поскольку backend для эксперимента
не запускался; сама страница отобразилась.

## Конкурентные изменения

Отдельная проверка через Playwright использовала два независимых Chromium-контекста
с отдельными WebSocket-соединениями к одной комнате `useSyncDemo`. После создания и начальной
синхронизации одной фигуры участники 20 раз почти одновременно задавали ей разные координаты
через `updateShape`.

Во всех 20 попытках оба клиента пришли к одинаковым итоговым координатам. ID фигуры сохранился,
дубликаты не возникли, объект не исчез. После перезагрузки второго участника согласованное
состояние сохранилось. Ошибок JavaScript не обнаружено. Тестовая фигура и временный скрипт
удалены после проверки.

Тест ограничен одной фигурой, двумя участниками и нормальным сетевым соединением.
Реальные drag-события, высокая задержка, отключение сети и большая нагрузка не проверялись.
Результат подтверждает сходимость в проверенном сценарии, но не доказывает полную надёжность
синхронизации и не проверяет постоянное хранение на собственном сервере.

## Self-hosted sync

Официальный `@tldraw/sync-core` предоставляет `TLSocketRoom` для серверной синхронизации
документа через WebSocket. Библиотеку можно разместить на собственном Node.js-сервере;
Cloudflare Durable Objects не обязателен. Для подключения к своему серверу frontend использует
`useSync` вместо `useSyncDemo`. См. [руководство по sync](https://tldraw.dev/docs/sync)
и [API TLSocketRoom](https://tldraw.dev/reference/sync-core/TLSocketRoom).

Предварительное разделение ответственности:

| Часть | Предполагаемая ответственность |
| --- | --- |
| Next.js + tldraw | Интерфейс редактора |
| NestJS + PostgreSQL | Пользователи, доски, бизнес-логика и права доступа |
| Отдельный Node.js sync-сервис | Синхронизация изменений через `TLSocketRoom` |
| SQLite | Возможное хранение состояния холста внутри sync-сервиса |

Это архитектурная гипотеза, а не принятое или реализованное решение. Собственный sync-сервер
в PoC не создавался, интеграция с NestJS не проверялась. Пользователи, доски и права в таблице
обозначают будущие обязанности backend, а не готовые модули.

SQLite — один из вариантов: для него есть готовый
[SQLiteSyncStorage](https://tldraw.dev/reference/sync-core/SQLiteSyncStorage).
Он не обязателен. Выбор хранения, проверка доступа к комнатам, восстановление после перезапуска,
резервное копирование и запуск в Docker требуют отдельного PoC.

## Ограничения

- По [документации useSyncDemo](https://tldraw.dev/reference/sync/useSyncDemo) комната доступна
  любому знающему её ID, данные удаляются примерно через сутки. Это не хранилище досок продукта.
- Демо зависит от внешнего sync-сервера и CDN ресурсов tldraw. Авторизация, права доступа,
  долговременное хранение и собственная инфраструктура остаются за рамками реализованного PoC.
- В установленном `@tldraw/sync/src/useSyncDemo.ts` загрузка файлов на стандартный демо-хост
  отключена. Для изображений и других файлов потребуется своё хранилище; в PoC оно не реализовано.
- Для production нужно отдельно согласовать лицензию и передать действующий ключ согласно
  [документации лицензирования](https://tldraw.dev/community/license). Успешный `next build`
  не подтверждает работу редактора на production-домене без ключа.
- Массовые доски, длительные сессии, восстановление после потери сети, touch и Safari/Firefox
  выходят за рамки проведённой проверки.

## Совместимость и проверки

Редактор установился без конфликтов peer dependencies. TypeScript и production-сборка
подтвердили совместимость с текущими Next.js, React и TypeScript проекта.
SSR редактора отключён; страница успешно проходит статическую генерацию Next.js.

Проверки запускаются из корня с Node через Volta:

```bash
volta run --node 26.13.1 pnpm typecheck
volta run --node 26.13.1 pnpm lint
volta run --node 26.13.1 pnpm build
```

Typecheck, полный lint и build прошли. Проблем совместимости, блокирующих PoC, не обнаружено.

## Пригодность для collab-board

tldraw подходит для следующего этапа оценки: готовый редактор покрывает базовые сценарии
Miro-подобной доски, а демо-синхронизация подключается одним хуком. Для приоритета быстрого
выпуска продукта это сильный кандидат. Решение о production требует проверки лицензии,
инфраструктуры sync, интеграции прав доступа и производительности на целевых размерах досок.
