# База данных и миграции

Пути относительно `apps/api/`:

| Путь | Содержимое |
| --- | --- |
| `src/prisma/` | Nest-модуль, PrismaService и фабрика PostgreSQL-адаптера |
| `src/generated/prisma/` | Генерируемый клиент; не коммитится |
| `prisma.config.ts` | Пути схемы и миграций, команда сидов, загрузка `.env` и URL |
| `prisma/schema/schema.prisma` | Datasource и генератор клиента |
| `prisma/schema/models/*.prisma` | Модели хранения |
| `prisma/migrations/<timestamp>_<name>/migration.sql` | Изменения структуры и обязательных данных |
| `prisma/seeds/*.seed.ts` | Тестовые данные |
| `prisma/seeds/index.ts` | Явный порядок сидов и общая транзакция |

## Подключение

Prisma использует `@prisma/adapter-pg`. Перед началом прослушивания HTTP
`PrismaService.onModuleInit` выполняет `SELECT 1`. Ошибка БД останавливает запуск.
Таймаут установления соединения — 5 секунд; это не ограничение времени любого
SQL-запроса. При завершении приложения соединения закрываются через `$disconnect()`.

## Формат моделей

Одна логическая модель или группа моделей агрегата — один файл
`kebab-case.prisma`. Модель называется в единственном числе, PascalCase.
Таблица — snake_case во множественном числе через `@@map` (`User` → `users`).
Первичный ключ: `String @id @default(uuid())`.
Модель хранения не является HTTP DTO или отдельным классом бизнес-логики.

Генератор `prisma-client` создаёт ESM-клиент в `src/generated/prisma`.
Импорты клиента и типов идут из `generated/prisma/client.js` по относительному
пути. `pnpm install` генерирует клиент без `.env`; команды работы с БД требуют
`DATABASE_URL`. Параметры URL должны соответствовать PostgreSQL из Compose.

## Миграции и сиды

Команды из корня репозитория:

```bash
pnpm --filter api exec prisma migrate dev --name add_users
pnpm db:generate
pnpm db:seed
```

Первая команда создаёт и применяет миграцию в dev-базе; имя приведено для примера.
Каталог миграции имеет формат `<YYYYMMDDHHmmss>_<name>`, timestamp в UTC.
`db:generate` обновляет клиент, не меняя БД. SQL и изменения моделей коммитятся вместе.

Для ручного дополнения SQL используется `migrate dev --create-only --name <name>`,
затем SQL редактируется и применяется через `pnpm db:migrate`.
Обязательные справочники и преобразования данных входят в миграцию.
Применённые миграции не редактируются и не переименовываются;
историю хранит `_prisma_migrations`. Готовые миграции применяются командой
`pnpm db:migrate:deploy`.

Чтобы изменить модель, которая уже влита в `develop/main` ветку — необходимо создавать новую миграцию.

Тестовые сиды запускаются только явно: `pnpm db:seed`.
Файл `<model>.seed.ts` получает `Prisma.TransactionClient`;
новый сид импортируется и вызывается в `index.ts` после своих зависимостей.
Нумерации нет. Повторный запуск безопасен благодаря `upsert` по уникальному
ключу или стабильному ID; `update: {}` сохраняет существующие записи.
Сейчас создаются тестовый пользователь и запись health-check.
В production тестовые сиды не запускаются.
