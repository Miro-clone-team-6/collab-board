## Модули и обработка запроса

Модуль — часть приложения с одной областью ответственности. Его файлы лежат рядом
в `src/modules/<name>/`, без обязательных вложенных слоёв.

| Элемент | Ответственность |
| --- | --- |
| `*.module.ts` | Регистрирует контроллеры и providers, подключает другие модули |
| `*.controller.ts` | Принимает HTTP-запрос, вызывает сценарий, задаёт HTTP-ответ |
| `*.dto.ts` | Описывает данные на границе HTTP; Nest DTO создаётся из общей Zod-схемы |
| `*.service.ts` | Выполняет логику модуля; текущий пример — проверка БД в health |
| Provider | Объект, который создаёт и передаёт Nest: сервис, репозиторий или конфигурация |

`imports` в `@Module` подключает модули, `controllers` регистрирует маршруты,
`providers` — зависимости, `exports` открывает providers другим модулям.
Nest передаёт зависимости через конструктор (DI). `@Injectable()` помечает класс
для работы с DI; `@Inject(token)` явно указывает, какую зависимость получить.

Пример пути запроса:

```text
GET /api/v1/health → HealthController → HealthService → PrismaService → SELECT 1
```

`HealthModule` содержит контроллер, сервис и DTO. Подключённый `UsersModule` —
заглушка без маршрутов и логики. `User` и `HealthCheck` в Prisma — модели хранения;
таблица `health_checks` не участвует в проверке доступности БД.

В бизнес-модулях обращения к БД размещаются в репозитории — классе, скрывающем
Prisma-запросы и типы хранения от остального модуля. Контроллер отвечает за HTTP,
сервис — за сценарий. Use case — отдельный класс одного сценария; выделяется,
когда это требуется логике. Репозитории, use case и интерфейсы заранее не создаются.
Правила предметной области не размещаются в DTO и контроллерах.
Обоснование структуры — [ADR 0003](../decisions/0003-backend-modules.md).

## Общий код API

| Путь в `apps/api/` | Назначение |
| --- | --- |
| `src/main.ts` | Создание приложения и запуск HTTP-сервера |
| `src/configure-app.ts` | Префикс, CORS, Helmet, cookies, Swagger и shutdown hooks |
| `src/app.module.ts` | Подключение модулей, конфигурации и глобального фильтра ошибок |
| `src/config/` | Загрузка и проверка настроек |
| `src/prisma/` | Подключение к БД |
| `src/errors/` | Ошибки приложения и их перевод в HTTP-ответы |

## HTTP-контракты

Схемы JSON находятся в `packages/contracts/src/<feature>/`, экспортируются из
`src/index.ts`; типы выводятся через `z.infer`. Пакет не содержит Nest-декораторов,
Prisma-моделей и React-кода. Даты в HTTP передаются строками.

Nest DTO наследует `createZodDto` общей схемы без повторения полей.
В health `ZodSerializerInterceptor` проверяет ответ по `@ZodSerializerDto`,
а Swagger использует тот же DTO. Глобальной валидации входящих DTO пока нет;
текущий эндпоинт не принимает тело запроса.

При добавлении эндпоинта согласуются схема, метод, путь и статусы ответа.
Изменения схемы и её потребителей входят в один PR.
Решение об общих схемах — [ADR 0002](../decisions/0002-shared-contracts.md).
