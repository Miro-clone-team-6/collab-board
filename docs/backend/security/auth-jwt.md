# 🔒 Безопасность и JWT-Аутентификация (`apps/api`)

> **Статус:** 🚧 На пересмотре — может описывать то, чего нет в коде. Источник правды — код и [architecture.md](../../architecture.md).

Сервис API CollabBoard реализует надежную двухточечную систему аутентификации на базе **JWT токенов** с хранением сессий и refresh токенов в защищенных cookies.

---

## 1. Схема JWT и Cookies

```text
┌─────────────────┐       ┌─────────────────┐
│  Access Token   │       │  Refresh Token  │
├─────────────────┤       ├─────────────────┤
│ Срок: 15 минут  │       │ Срок: 7 дней    │
│ В теле ответа   │       │ В HttpOnly Cookie│
│ В заголовке     │       │ SameSite=Lax    │
│ Authorization   │       │ Path=/api/v1/auth│
└─────────────────┘       └─────────────────┘
```

1. **Access Token (короткоживущий, 15 мин)**:
   - Передается в теле JSON ответа при логине/регистрации/обновлении токена.
   - Клиент прикрепляет его в заголовок `Authorization: Bearer <token>` для доступа к защищенным REST эндпоинтам.
   - Содержит claims: `sub` (ID пользователя), `sid` (ID сессии), `email`, `exp`.
2. **Refresh Token (долгоживущий, 7 дней)**:
   - Передается **только** в `HttpOnly`, `Secure` (в prod), `SameSite=Lax` Cookie.
   - JavaScript в браузере не имеет к нему доступа, что защищает от XSS атак.
   - Путь cookie ограничен `/api/v1/auth`, чтобы браузер не отправлял его на каждый запрос.

## 2. Хэширование паролей

Пароли хэшируются с использованием стойких алгоритмов (**Argon2id** / **bcrypt**) перед сохранением в PostgreSQL:
* Сырые пароли никогда не пишутся в базу данных или логи.
* При выборке пользователя из БД всегда используется исключающий `select`:
  ```typescript
  const user = await prisma.user.findUnique({
    where: { id },
    select: { id: true, email: true, name: true, createdAt: true },
  });
  ```
