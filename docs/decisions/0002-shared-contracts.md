# 0002. Общие HTTP-контракты на Zod

- **Статус:** 💬 Обсуждается
- **Дата:** 2026-11-11
- Заменяет [ADR 0001](./0001-api-contracts.md).

## Решение

`packages/contracts` хранит схемы HTTP-запросов и ответов на Zod и типы через
`z.infer`. Одна тема — каталог в `src/`. Пакет не зависит от приложений, Nest,
Prisma или React. Модели хранения и доменные сущности остаются на бэкенде.

Nest DTO наследует `createZodDto` схемы. Для health ответ проверяет
`ZodSerializerInterceptor`; Swagger строится по той же схеме через nestjs-zod.
Фронтенд использует обычный fetch и проверяет JSON схемой; React Query остаётся
во фронтенде. Клиент и файлы спецификации не генерируем. Orval, `packages/api`
и дублирующие DTO удалены; `packages/dto` переименован в `packages/contracts`.
Настройки сборки общего пакета через tsc и общий tsconfig сохранены.

## Параллельная разработка

Сначала согласуем схему, HTTP-метод, путь и статусы. Фронтенд работает с моками
по контракту, бэкенд реализует поведение. Типы и схемы доступны без запуска API.
Общий пакет не проверяет совпадение URL и методов: это проверяется при интеграции.
Для независимых релизов изменения контракта должны быть обратно совместимы;
удаление полей и новые обязательные поля требуют согласованного перехода.

## Ограничения

Реализован только GET `/api/v1/health`, принимающий запрос без тела.
Глобальная валидация входящих DTO пока не подключена. Общий пакет собирается
перед запуском Nest; после изменения схемы нужен build или watch пакета.
