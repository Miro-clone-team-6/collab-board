Общие границы описаны в архитектуре, детали — в разделе соответствующей части
системы. Раздел `devops/` добавляется с появлением инструкций по эксплуатации.
Обоснования и рассмотренные альтернативы хранятся только в `decisions/`.
В остальных документах описывается устройство или порядок действий.

Правило описывается в одном месте; другие документы ссылаются на него.
При изменении поведения обновляется соответствующий документ в том же PR.

При редактировании документации следует опускать малозначимые детали, не лить воду и не перебарщивать с `.md` форматированием. Код — рассказывает о том, «что делает». Документация рассказывает «почему» и «в каком контексте».

Не задавать избыточных и обратных ссылок: ссылки в документации идут только сверху-вниз или горизонтально. Пример: внутри описания обработки ошибок не ссылаться на описание API, страница которого уже перенаправила нас на конкретный обработчик.
